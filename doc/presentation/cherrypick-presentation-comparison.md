# Матрица выбора

**Приложение без смены контекста, нет логаута** → `get_it` или `kiwi`. Не усложняйте

**Состояние тесно связано с UI, нужен кеш и реактивность** → `riverpod`. Это его задача

**Объект принадлежит экрану и не переживает его** → `provider`

**Нужны скоупы и важнее всего гарантии компилятора** → `yx_scope`

**Нужны скоупы, важнее минимум понятий и динамика, готовы платить рантаймом** → `cherrypick`

# Резерв 7: полный список аннотаций CherryPick

| Аннотация | Что делает |
|---|---|
| `@module()` | Класс — DI-модуль |
| `@provide()` | Метод регистрируется как провайдер |
| `@singleton()` | Один экземпляр на скоуп |
| `@instance()` | Новый экземпляр на каждый запрос |
| `@named('...')` | Именованный биндинг |
| `@params()` | Параметр приходит при резолвинге |
| `@injectable()` | Класс участвует в инъекции полей |
| `@inject()` | Поле заполняется автоматически |
| `@scope('...')` | Поле резолвится из указанного скоупа |

# Резерв 8: «Можно ли мигрировать постепенно?»

```dart
// легаси остаётся на get_it
GetIt.I.registerSingleton<LegacyService>(LegacyService());

// новая фича — на скоупах, с мостом в один биндинг
class NewFeatureModule extends Module {
  @override
  void builder(Scope currentScope) {
    bind<LegacyService>().toProvide(() => GetIt.I<LegacyService>());
    bind<NewRepo>().toProvide(() => NewRepo(currentScope.resolve<LegacyService>()));
  }
}
```

**Порядок:** новые фичи на скоупах → мост для легаси → сессионный скоуп → тесты → корень

Каждый шаг самодостаточен: можно остановиться на любом
