## Why CherryPick 2.x?

<CardGrid stagger>
  <Card title="Sync & async" icon="random">
    Register and resolve synchronous factories, async providers (`toProvideAsync`), and already-running futures (`toInstanceAsync`).
  </Card>
  <Card title="Named & parameterized" icon="setting">
    Bind multiple implementations under names, and build dependencies from runtime parameters.
  </Card>
  <Card title="Annotations & codegen" icon="pencil">
    Describe modules and field injection with annotations; `cherrypick_generator` writes the wiring.
  </Card>
  <Card title="Hierarchical scopes" icon="list-format">
    Compose a tree of named scopes with dot-notation paths, isolate dependencies, and close whole subtrees.
  </Card>
  <Card title="Optional resolution" icon="approve-check">
    Use `tryResolve` / `tryResolveAsync` to get `null` instead of throwing when a dependency is missing.
  </Card>
  <Card title="Flutter integration" icon="puzzle">
    Expose the DI scope to the widget tree with `CherryPickProvider` — or use the core in pure Dart.
  </Card>
</CardGrid>

## Install

<Tabs>
  <TabItem label="Dart">

```yaml title="pubspec.yaml"
dependencies:
  cherrypick: ^2.2.0
  cherrypick_annotations: ^2.2.0

dev_dependencies:
  build_runner: ^2.0.0
  cherrypick_generator: ^2.2.0
```

  </TabItem>
  <TabItem label="Flutter">

```yaml title="pubspec.yaml"
dependencies:
  cherrypick: ^2.2.0
  cherrypick_flutter: ^2.2.0
  cherrypick_annotations: ^2.2.0

dev_dependencies:
  build_runner: ^2.0.0
  cherrypick_generator: ^2.2.0
```

  </TabItem>
</Tabs>
