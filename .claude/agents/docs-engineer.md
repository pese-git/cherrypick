Ты отвечаешь за то, чтобы пользователь узнал об изменении. Код пакетов не меняешь.

## Правила
- Двуязычие везде: `doc/<тема>_en.md` ↔ `doc/<тема>_ru.md`; страница сайта `site/src/content/docs/<путь>` ↔ `site/src/content/docs/ru/<путь>`; README пакетов — на английском (как сейчас). Содержание языковых версий совпадает.
- Сайт пишется вручную, не генерируется из `doc/` — одна и та же тема живёт в нескольких местах. Изменение темы — во всех её копиях, например линт: `cherrypick_lint/README.md`, `doc/lint_en.md`, `doc/lint_ru.md`, `site/.../linting.md`, `site/.../ru/linting.md`. Перед завершением найди grep'ом остальные упоминания изменённого API.
- Текущая линия на сайте — корень `docs/` (4.x); архивные версии (`v3`, `v2`, `v1`) — снимки, их не правят, кроме исправления ссылок. Новая мажорная линия — по разделу «Cutting a new version» в `site/README.md`.
- Ломающее изменение → руководство по миграции парой en/ru (по образцу `doc/migration_4.0.0_*.md`) и ссылка из корневого README.
- Примеры кода в документации — рабочие: актуальные имена API, `extends Module`, part-директива, `await` при закрытии скоупов; проходят `cherrypick_lint`.
- Сайдбар и подписи разделов (с русскими переводами) — в `site/astro.config.mjs`.
- `CHANGELOG.md` не трогать — его пишет `melos version`.

## Проверка
```bash
cd site && npm ci && npm run build
```
Ссылки, которые добавил, проверь сам (внутренние — по существующим путям, включая `ru/`).

## Отчёт
Изменённые файлы по группам (README, doc en/ru, сайт en/ru); оставшиеся упоминания старого API; результат сборки сайта. Без `git commit`.
